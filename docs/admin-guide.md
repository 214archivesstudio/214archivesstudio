# 어드민 사용 가이드

작가가 일상 운영에서 마주치는 시나리오 중심 튜토리얼. 각 시나리오는 (1) 무엇을 클릭 (2) 무엇이 보여야 정상 (3) 막힘 대응 순으로 정리.

- **어드민**: <https://www.214archives.com/admin>
- **로그인**: 등록된 이메일·비밀번호 (관리자에게 발급 요청)
- **공개 사이트 반영까지**: 보통 1~3분 (Vercel 빌드 + 배포)
- **포스트 목록 순서**: 최근에 수정한 순. 방금 만들거나 고친 게시물이 맨 위에 옵니다 (섹션별로 보려면 섹션 탭)

---

## 0. 핵심 개념 (한 번만 읽기)

| 개념 | 의미 |
|---|---|
| **공개 (published)** | 게시물에 붙는 의도 플래그. 토글만 누른 시점에는 아직 공개 사이트에 안 나옴 |
| **변경사항 게시** | 그동안 표시·수정한 모든 변경을 한 번에 공개 사이트에 반영하는 액션 |
| **DRIFT** | "공개"로 표시했지만 아직 사이트에 반영 안 된 변경 개수. Header 우측 배지에 표시 |

> 💡 토글 = "공개하겠다는 의도", **변경사항 게시 클릭 = 실제 배포**. 두 단계로 나뉘어 있는 이유는 여러 게시물을 모았다가 한 번에 올리기 위함.

## 시나리오 1 — 새 게시물 올리기

### 예시: 새 여행 사진 묶음을 archives에 올림

1. `/admin/posts` → 우측 상단 **"+ 새 포스트"** 클릭
2. **섹션 선택** 카드 5개 중 하나 선택 (Showreel / Archives / Film / Photography / Personal)
3. 폼이 나타나면 입력:
   - 제목, 슬러그 (영문 소문자·숫자·하이픈), 날짜 (YYYY-MM-DD). 슬러그는 입력을 멈추면 자동으로 중복 검사 — "사용 가능" 또는 "이미 사용 중인 슬러그입니다" 표시
   - Showreel·Film·Personal이면 **영상 URL** (YouTube/Vimeo) — 붙여넣는 즉시 아래에 플레이어 미리보기가 뜸. 안 뜨면 URL이 잘못된 것
   - **썸네일 업로드** 클릭 → Cloudinary 위젯에서 이미지 선택
   - 섹션별 추가 필드 (Archives면 도시·연도 라벨, Photography면 클라이언트 등)
   - **Film이면 영상 썸네일**: **영상 업로드** 클릭 → mp4/webm/mov 선택 (가로 영상 권장, 200MB 이하). 업로드 직후 폼 안에서 미리보기가 자동 재생됨. 앞 10초만 잘라 쓰므로 긴 영상도 그대로 올려도 됨. 이미 URL이 있다면 아래 **고급: URL 직접 입력**에 붙여넣기
4. **생성** 클릭 → 자동으로 편집 화면으로 이동, 상단에 "썸네일·기본 정보가 저장됐어요. 이제 갤러리를 추가하세요" 안내

### 갤러리 사진 추가 (편집 화면에서)
5. **미디어 → 이미지 업로드** → Cloudinary 위젯에서 여러 사진 동시 선택 가능
6. 업로드된 사진은 그리드 끝에 차례로 추가됨
7. 각 사진 카드의 **alt 텍스트** 입력란에 설명 입력 → 포커스 빼면 자동 저장 (스크린리더용)

### 사진 순서 변경
8. 사진 카드를 **드래그**해서 원하는 위치로 이동
9. 키보드만으로도 가능: Tab으로 카드 포커스 → Space로 잡기 → 화살표로 이동 → Space로 놓기

### 게시 (공개 사이트에 띄우기)
10. 우측 상단 **공개 상태** 카드에서 **"공개"** 클릭
11. 우측 하단에 토스트: *"'공개'로 표시했어요. 사이트에 반영하려면 대시보드 → '변경사항 게시'를 눌러주세요."*
12. Header 우측에 **DRIFT · 1** 배지 표시됨
13. 배지 클릭 또는 **Dashboard** 메뉴로 이동
14. **게시 패널 → 변경사항 게시** 클릭
15. ~30초 후 상태가 `success`로 바뀌고 배지가 사라짐 → 1~3분 뒤 공개 사이트(`/{섹션}/{슬러그}`)에서 확인

### 막힘
| 증상 | 해결 |
|---|---|
| 썸네일 업로드 위젯이 안 뜸 | 팝업 차단 해제 후 재시도 |
| 생성 버튼 누르면 폼만 리셋 | 콘솔 에러 확인. 보통 슬러그 중복 — 입력 중 "이미 사용 중인 슬러그입니다" 경고가 떴는지 확인 |
| 게시 후에도 사이트에 안 보임 | (a) 변경사항 게시를 안 눌렀나 확인 (b) Vercel 빌드 진행 중일 수 있으니 2~3분 대기 |
| 토글이 동작 안 함 | 본인이 admin 역할인지 확인 (editor는 published 토글 불가) |

## 시나리오 2 — 기존 게시물 수정 (오타·설명 보강)

1. `/admin/posts`에서 해당 게시물 클릭
2. 원하는 필드 수정 (제목, 설명, alt 등)
3. 맨 아래 **저장** 클릭
4. **Dashboard → 변경사항 게시** 클릭 → 1~3분 후 사이트 반영

> 💡 **저장 ≠ 게시.** 저장은 DB에만 기록. 사이트 반영은 반드시 "변경사항 게시" 클릭이 필요.

---

## 시나리오 3 — 사진 일부 교체 / 삭제

1. 편집 화면 미디어 섹션에서 교체할 사진 카드 우상단 **✕** (또는 **삭제** 버튼)
2. 확인 다이얼로그 → **삭제**
3. 새 사진은 **이미지 업로드**로 추가 후 드래그로 원하는 위치 이동
4. **변경사항 게시**로 사이트 반영

---

## 시나리오 4 — Personal 섹션에 영상 추가

> 📌 **영상 카드는 Personal 섹션에서만 추가 가능.** Archives·Film·Photography·Showreel에는 영상 추가 버튼이 없음 (Film·Showreel은 게시물 자체가 영상이므로 폼 상단 "영상 URL" 필드 사용). Film 카드에 마우스를 올렸을 때 재생되는 **영상 썸네일**은 별개 — 폼의 "영상 썸네일" 업로더로 올림 (시나리오 1 참고).

1. Personal 게시물 편집 화면 → **미디어 → 영상 추가**
2. 모달에 YouTube 또는 Vimeo URL 입력 (예: `https://youtu.be/abc123`)
3. **추가** → 영상 카드가 그리드에 추가됨 (YouTube는 영상 썸네일이 카드에 표시됨, Vimeo는 플랫폼·ID 텍스트)
4. 잘못된 URL이면 *"유효한 YouTube 또는 Vimeo URL이 아닙니다"* 표시 → 다시 입력

## 시나리오 5 — 여러 게시물 모아서 한 번에 게시

빌드 한도 절약 + 효율적인 워크플로.

1. 오전: 게시물 A 새로 만들고 **공개** 토글
2. 오후: 게시물 B 사진 추가, C 오타 수정, 둘 다 이미 공개 상태
3. Header 배지에 **DRIFT · 3** 표시
4. 모든 변경이 끝나면 Dashboard로 이동
5. **게시 패널** 에서 어떤 게시물이 미반영인지 확인
6. **변경사항 게시** 한 번 클릭 → 3건 모두 한 번에 사이트 반영

> 💡 작가 운영 빈도가 잦지 않다면 매번 즉시 게시해도 무방. Vercel 무료 플랜은 월 6000분 빌드라 일반 운영에서 한계에 부딪힐 일 없음.

---

## 시나리오 6 — 게시물 비공개로 전환

사이트에서 일시적으로 내리고 싶을 때 (DB는 유지).

1. 게시물 편집 화면 → 공개 상태 카드 → **초안** 클릭
2. "초안으로 전환할까요?" 확인창 → **초안으로 전환** (실수 방지용. 취소하면 아무 변화 없음)
3. 토스트 확인 후 Dashboard → **변경사항 게시**
4. 1~3분 후 공개 사이트에서 사라짐 (DB에는 그대로 남아 언제든 다시 공개 가능)

---

## 시나리오 7 — 게시물 완전 삭제

복구 불가. 신중하게.

1. 편집 화면 맨 아래 **위험 영역 → 삭제…** 클릭
2. 확인 다이얼로그에서 한 번 더 **삭제**
3. Supabase에서 즉시 제거 (연결된 미디어 메타도 함께 삭제)
4. 사이트 반영을 위해 **변경사항 게시** 클릭

> ⚠️ Cloudinary에 업로드된 이미지 파일 자체는 남음. 완전히 지우려면 [Cloudinary Dashboard](https://cloudinary.com/console)에서 별도 삭제.

---

## 시나리오 8 — 첫 번째 게시 (처음 운영 시작할 때)

DRIFT 배지가 **"최초 반영 N건 대기"** (초록색)로 표시됨. 정상.

1. 모든 기존 게시물이 공개 상태인지 확인 (Dashboard "공개됨" 카운트)
2. **변경사항 게시** 1회 클릭 → 전체 동기화
3. 이후부터는 DRIFT 카운터가 실제 변경 건수만 표시

## 자주 마주치는 막힘

| 증상 | 원인 / 해결 |
|---|---|
| **로그인 직후 redirect 무한 루프** | 계정에 admin 역할 미부여. 관리자에게 user_roles 등록 요청 |
| **게시 클릭 후 "401 Unauthorized: Bad credentials"** | GitHub PAT 만료. 관리자에게 토큰 갱신 요청 |
| **게시 했는데 사이트는 옛날 그대로** | Vercel 빌드 진행 중. 보통 1~3분. https://vercel.com/dashboard에서 deployment 상태 확인 |
| **게시 패널에 TIMEOUT 표시** | 10분 안에 빌드가 끝나지 않아 자동으로 실패 처리됨 (보통 GitHub Actions 쪽 문제). 최근 활동의 **실행 로그 ↗** 링크에서 원인 확인 후 **다시 게시** |
| **이미지가 뿌옇거나 안 뜸** | Cloudinary 전송 지연. 새로고침 후 보통 해결 |
| **Film 영상 썸네일 업로드 직후 미리보기가 몇 초간 비어 있음** | Cloudinary가 압축본을 처음 생성하는 중. 5~10초 후 자동 재생. 이후 방문부터는 즉시 |
| **영상 업로더 대신 회색 안내 박스만 보임** | `NEXT_PUBLIC_CLOUDINARY_VIDEO_UPLOAD_PRESET` 환경 변수 미설정. 관리자에게 요청 |
| **드래그 정렬이 PC에서 안 됨** | Trackpad/마우스 짧게 더 분명히 잡기. 안 되면 키보드 정렬 (Tab → Space → 화살표 → Space) |
| **새로고침하면 입력값이 사라짐** | 저장 안 누르고 새로고침함. 폼 입력 후 반드시 **저장** 먼저 |
